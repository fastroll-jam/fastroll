## About

FastRoll is a Rust implementation of a validator node for JAM (Join-Accumulate Machine), formally specified in the [Graypaper](https://github.com/gavofyork/graypaper).

## Status

- **[2026-09-27]** 🏆 Awarded [JAM Prize](https://jam.web3.foundation/) Milestone 1 (IMPORTER).
- **[2026-05-25]** 🎉 Passed Milestone 1 fuzzing, successfully importing 1.3 million blocks generated by the fuzzer.
- Successfully imports blocks and yields valid post-states as specified in the Graypaper ([supported version](./common/src/versions.rs)).
- WIP: Block authoring, auditing, networking, and performance optimization.

## Build and Run

The `fastroll` binary currently runs as a fuzz target of the [fuzz protocol](https://github.com/jam-conformance/jam-fuzzing/tree/cddba17d4a0798a7c794e003df0c21140e1fc09a/fuzz-proto). The JAM node runner is under active development and requires dev accounts.

Building requires the stable Rust toolchain and Clang.

```bash
# Build
cargo build --features "tiny,fuzz"

# Run the fuzz target on its default socket
cargo run --features "tiny,fuzz" -- fuzz --socket "/tmp/jam_target.sock"
```

| Feature | Purpose |
|---|---|
| `tiny` | Selects the [tiny](https://docs.jamcha.in/basics/chain-spec/tiny) chain spec. |
| `full` | Selects the [full](https://docs.jamcha.in/basics/chain-spec/full) chain spec, also used when `tiny` is off. |
| `fuzz` | Skips timeslot validation against the wall clock. |

### Run the Docker image

Each [release](RELEASING.md) publishes an image with the `tiny` and `full` fuzz targets for `linux/amd64`:

```bash
docker run --rm \
  -v /tmp/fastroll:/fastroll \
  -e JAM_FUZZ=1 \
  -e JAM_FUZZ_SPEC=tiny \
  -e JAM_FUZZ_DATA_PATH=/fastroll/data \
  -e JAM_FUZZ_SOCK_PATH=/fastroll/jam_target.sock \
  ghcr.io/fastroll-jam/fastroll:latest
```

| Variable | Description |
|---|---|
| `JAM_FUZZ` | Runs the fuzz target when defined. Otherwise the container passes its arguments to the `tiny` binary. |
| `JAM_FUZZ_SPEC` | Chain spec, `tiny` or `full`. |
| `JAM_FUZZ_DATA_PATH` | Data directory, created at startup. |
| `JAM_FUZZ_SOCK_PATH` | Unix socket path for the fuzzer. Mount its directory to reach it from the host. |
| `JAM_FUZZ_LOG_LEVEL` | Optional log level, `error`, `warn`, `info`, `debug` or `trace`. An explicit `RUST_LOG` takes precedence. |

## Conformance Testing

### Test vectors

Test vectors take about 2 GiB and are pinned as Git submodules under `integration/`. Set them up before running the tests:

```bash
./scripts/setup-test-vectors.sh
```

| Option | Purpose |
|---|---|
| `--verify` | Checks an existing checkout without downloading anything. |
| `--force` | Recreates all vector submodules, discarding their local changes. |

Avoid `git submodule update --remote`, because upstream branches may target newer Graypaper versions.

### Running tests

```bash
# All tests
cargo nextest run --workspace --no-fail-fast --features "tiny,fuzz" --release

# All block import tests
cargo nextest run block_import_ --no-fail-fast --features "tiny,fuzz" --release

# Block import tests of one group
cargo nextest run block_import_safrole_ --no-fail-fast --features "tiny,fuzz" --release
```

- Block import groups: `fallback`, `safrole`, `storage`, `storage_light`, `preimages`, `preimages_light`, `fuzzy`, `fuzzy_light`, and `conformance` for the fuzzing traces.
- Groups in `IGNORED_TRACE_GROUPS` of [integration/build.rs](integration/build.rs) only run with `--run-ignored all`.
- Set `RUST_LOG` to filter logs, and add `--no-capture` to print them (e.g. `RUST_LOG="fr_node=debug"`).

## Benchmarking

Run a per-block import benchmark over a jam-test-vectors trace group, selected by `TRACE_KIND`:

```bash
TRACE_KIND=safrole cargo bench -p fr-node-bench --bench block_importer --features tiny -- --sample-size 10 --measurement-time 10
```

Each run writes `total_avg_ms` and `per_block_avg_ms` to `node-bench/reports/<trace_label>_<unix_timestamp>.log`. The averages include warm-up iterations and exclude handshake and initialization time.

Fuzzing performance across implementations is available in the [reports](https://github.com/jam-conformance/jam-fuzzing/tree/main/fuzz-perf) and on the [dashboard](https://paritytech.github.io/jam-conformance-dashboard/).
